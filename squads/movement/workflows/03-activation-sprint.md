# Sprint de Ativação: Comunidade + Creators + Distribuição

## Objetivo

Executar sprint coordenado de ativação que sincroniza comunidade, creators, paid media e PR para amplificar a mensagem do movimento de forma orquestrada, maximizando impacto através da sinergia entre canais.

## Diagrama de Fases

```
[FASE 1]          [FASE 2]          [FASE 3]          [FASE 4]          [FASE 5]
Planejamento  →   Preparação    →   Execução      →   Amplificação  →   Debrief
do Sprint         de Assets          Coordenada        e Otimização      e Report
   |                 |                  |                  |                  |
   v                 v                  v                  v                  v
Objetivos,       Creators          Comunidade +        Paid media       Sprint
timeline,        briefados,        creators +          otimizado,       Report com
budget           assets prontos    PR ativados         UGC amplificado  learnings
```

## Fases Detalhadas

### Fase 1: Planejamento do Sprint (Dia 1-3)

**Agentes:** ativador-chefe, estrategista-movimento

**Inputs:**
- Prioridades do mês (do monthly review)
- Calendar de ativações e datas relevantes
- Budget disponível (creators, paid, PR)
- Assets disponíveis na biblioteca
- Win Conditions vigentes

**Ações:**
1. Definir objetivo do sprint: awareness, community growth, engagement, conversão
2. Selecionar canais a ativar: quais combinações de comunidade + creators + paid + PR
3. Criar timeline detalhado: quem faz o quê, quando, em qual canal
4. Alocar budget por canal e ação
5. Definir métricas de sucesso do sprint

**Outputs:**
- Sprint Plan com timeline e budget
- Métricas de sucesso definidas
- Responsáveis alocados

**Decision Gate:**
- Plan aprovado pelo Arquiteto → avançar
- Budget insuficiente → reduzir escopo e repriorizar

### Fase 2: Preparação de Assets (Dia 4-8)

**Agentes:** ativador-chefe, manifestador-criativo, community-builder

**Inputs:**
- Sprint Plan aprovado
- Biblioteca de assets
- Creator Briefs template
- PR angles disponíveis

**Ações:**
1. Verificar assets existentes e identificar gaps de produção
2. Produzir ou adaptar assets necessários para cada canal
3. Enviar briefs para creators selecionados e acompanhar confirmação
4. Preparar pitches de PR para veículos target
5. Configurar campanhas de paid media (segmentação, tracking, criativos)
6. Preparar comunidade: teasers, convites para ritual especial

**Outputs:**
- Assets adaptados por canal
- Creators briefados e confirmados
- Campanhas de paid configuradas
- PR pitches prontos
- Comunidade aquecida

**Decision Gate:**
- Tudo preparado → avançar para execução
- Creator não confirmou → ativar backup ou ajustar plan

### Fase 3: Execução Coordenada (Dia 9-15)

**Agentes:** ativador-chefe, community-builder

**Inputs:**
- Sprint Plan com timeline dia a dia
- Assets finalizados
- Canais configurados

**Ações:**
1. Dia 9-10: Ativar comunidade (teaser, ritual especial, provocação de conversa)
2. Dia 11-12: Creators publicam conteúdo (coordenação de timing)
3. Dia 11-13: PR outreach executado (pitches enviados, exclusivas negociadas)
4. Dia 12-15: Paid media ativado para amplificar top conteúdo orgânico
5. Monitorar em tempo real: engajamento, sentimento, conversas derivadas
6. Responder e engajar nas conversas geradas
7. Capturar UGC e conteúdo orgânico para amplificação

**Outputs:**
- Ativações executadas em todos os canais
- Métricas de tempo real capturadas
- UGC coletado
- Engajamento realizado

**Decision Gate:**
- Tração positiva → manter curso e considerar ampliar
- Tração fraca → ajustar messaging ou redirecionar budget
- Backlash → acionar protocolo de crise

### Fase 4: Amplificação e Otimização (Dia 16-22)

**Agentes:** ativador-chefe, analista-impacto

**Inputs:**
- Dados de performance da Fase 3
- UGC capturado
- Conteúdo orgânico de destaque

**Ações:**
1. Identificar top performers: qual conteúdo/canal/creator gerou mais resultado
2. Escalar budget de paid para top performers
3. Amplificar UGC: repostar, destacar criadores, criar compilações
4. Nutrir conversas derivadas: participar, contribuir, manter momentum
5. Otimizar campanhas diariamente: kill underperformers, scale winners
6. Capturar cobertura de PR e amplificar

**Outputs:**
- Campanhas otimizadas
- UGC amplificado
- Conversas nutridas
- Cobertura de PR amplificada

**Decision Gate:**
- ROI positivo → manter amplificação até final do sprint
- ROI negativo → reduzir spend e focar em orgânico

### Fase 5: Debrief e Report (Dia 23-25)

**Agentes:** analista-impacto, ativador-chefe

**Inputs:**
- Dados completos do sprint
- Win Conditions para comparação
- Feedback qualitativo coletado

**Ações:**
1. Consolidar todas as métricas: alcance, engajamento, community growth, conversão
2. Calcular ROI do sprint por canal
3. Analisar o que funcionou e o que não (com dados, não opiniões)
4. Documentar learnings acionáveis
5. Produzir Sprint Report com recomendações para o próximo

**Outputs:**
- Sprint Report completo
- ROI por canal calculado
- Learnings documentados
- Recomendações para próximo sprint

**Decision Gate:**
- Sprint bem-sucedido → replicar modelo com ajustes
- Sprint parcial → ajustar mix de canais e messaging
- Sprint falhou → revisão profunda antes do próximo

## Cadência

- **Ciclo completo:** 25 dias (mensal)
- **Dia 1-3:** Planejamento
- **Dia 4-8:** Preparação
- **Dia 9-15:** Execução
- **Dia 16-22:** Amplificação
- **Dia 23-25:** Debrief

## Artefatos Produzidos

- Sprint Plan
- Assets adaptados por canal
- Campanhas configuradas
- Sprint Report com métricas e learnings

## Métricas de Sucesso

| Métrica | Meta |
|---------|------|
| Alcance total do sprint | Definido por objetivo |
| Community growth | >= meta mensal |
| Engajamento rate | >= média dos 3 últimos meses |
| Creator content published | 100% dos confirmados |
| Paid ROI | >= 1.5x |
| Sprint Report entregue | Em até 3 dias pós-sprint |

### Regras de Fluxo
- **Quality Gate entre fases:** Fase 1→2: plan aprovado pelo Architect; Fase 2→3: tudo preparado; Fase 3→4: tração positiva; Fase 4→5: ROI positivo

- **Escalation:** Se backlash durante execução → acionar `workflows/06-crisis-and-backlash.md`
- **Handoff:** Sprint Report alimenta → `workflows/04-measure-and-learn.md` e `workflows/05-ralphloop-kaizen-weekly.md`
