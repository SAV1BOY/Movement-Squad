# Template Usage Guide — Como Usar Templates

## Visão Geral

Templates são pontos de partida padronizados para criação de deliverables.
Eles garantem consistência, aceleram a execução e reduzem a carga cognitiva
de "começar do zero".

## Filosofia dos Templates

Templates não são camisas de força. São andaimes — usam-se para construir,
e depois removem-se quando a estrutura se sustenta sozinha. Adapte o template
ao contexto, nunca o contrário.

## Como Usar

### Passo 1: Escolha o Template Certo
Consulte a lista abaixo ou busque em `squads/movement/templates/`.
Se não encontrar um template adequado, considere criar um novo.

### Passo 2: Faça uma Cópia
Nunca edite o template original. Copie para o diretório correto e
renomeie seguindo `naming-conventions.md`.

### Passo 3: Leia as Instruções
Cada template tem instruções embutidas (em comentários ou blocos
marcados). Leia todas antes de preencher.

### Passo 4: Preencha e Adapte
- Substitua todos os placeholders por conteúdo real
- Remova seções que não se aplicam (documente por que removeu)
- Adicione seções extras se o contexto pedir
- Remova instruções/comentários do template antes de finalizar

### Passo 5: Revise com a Checklist
Se existe checklist associada, use-a para validar o deliverable.

## Onde Encontrar

Templates ficam em `squads/movement/templates/`. Organizados por categoria.

## Regras de Uso

1. **Nunca edite o original** — Sempre trabalhe em cópias
2. **Remova placeholders** — Nenhum "[INSERIR AQUI]" no deliverable final
3. **Adapte sem medo** — Templates são sugestões, não ordens
4. **Documente adaptações** — Se mudou algo significativo, anote
5. **Sugira melhorias** — Se o template pode ser melhor, contribua

## Quando Criar um Novo Template

Crie quando:
- Um tipo de deliverable é criado mais de 3 vezes
- A qualidade varia muito entre versões do mesmo tipo
- Novos membros demoram para entender o formato esperado
- Existe um "formato ideal" que deveria ser padrão

## Como Criar um Novo Template

1. Pegue o melhor exemplo existente do deliverable
2. Generalize: substitua conteúdo específico por placeholders
3. Adicione instruções/comentários em cada seção
4. Teste com alguém que nunca usou
5. Itere com base no feedback
6. Adicione ao diretório `templates/` seguindo naming conventions
