# Retrospectiva Pós-Lançamento

## Objetivo

Conduzir retrospectiva estruturada após cada lançamento ou ciclo relevante do
movimento para extrair aprendizados acionáveis. Sem retrospectiva, erros se
repetem e acertos não são replicados.

## Checklist

### Preparação da Retrospectiva

- [ ] Retrospectiva está agendada em até 7 dias após o fim do lançamento/ciclo
- [ ] Dados de performance estão coletados e acessíveis antes da sessão
- [ ] Todos os envolvidos na execução estão convidados (não apenas liderança)
- [ ] Timeline do que aconteceu está documentada cronologicamente (fatos, não interpretações)
- [ ] Ambiente seguro para feedback honesto está garantido (sem retaliação)

### Análise de Resultados

- [ ] Comparação meta vs realizado está documentada para cada KPI definido previamente
- [ ] Desvios positivos (superou meta) e negativos (ficou abaixo) estão quantificados
- [ ] Custo real vs budget planejado está calculado
- [ ] Timeline real vs planejada está comparada (o que atrasou e por quê)
- [ ] Impacto não previsto (positivo ou negativo) está registrado

### Extração de Aprendizados

- [ ] Pelo menos 3 "o que funcionou bem" estão documentados com evidência
- [ ] Pelo menos 3 "o que não funcionou" estão documentados com evidência
- [ ] Para cada "não funcionou", root cause está identificada (não apenas sintoma)
- [ ] Para cada "funcionou", fatores replicáveis estão identificados
- [ ] Pelo menos 1 "surpresa" (algo inesperado) está documentada com aprendizado

### Ações Pós-Retrospectiva

- [ ] Cada aprendizado tem pelo menos 1 ação concreta derivada com owner e prazo
- [ ] Ações de melhoria estão priorizadas por impacto e facilidade de implementação
- [ ] Aprendizados são publicados para todo o squad (transparência total)
- [ ] Playbook do movimento é atualizado com novos aprendizados
- [ ] Follow-up de ações é agendado para 30 dias após a retrospectiva

## Critérios de Aprovação

- Todos os itens de "Preparação" devem estar completos antes da sessão
- Todos os itens de "Análise de Resultados" devem estar completos
- Pelo menos 4 de 5 itens de "Extração de Aprendizados" devem estar completos
- Todos os itens de "Ações Pós-Retrospectiva" devem estar completos

## Ação se Falhar

1. Se retrospectiva não aconteceu: agendar imediatamente (relevância diminui com tempo)
2. Se dados faltam: coletar o que for possível e documentar gaps de instrumentação
3. Se participação é baixa: reduzir duração para 45 min e focar nos 3 pontos mais críticos
4. Se ações não estão sendo implementadas: escalar ao chief como problema de processo
5. Se aprendizados se repetem: questionar se o processo de melhoria está funcionando
