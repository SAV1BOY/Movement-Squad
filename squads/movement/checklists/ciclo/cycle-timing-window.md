# Validação de Janela de Timing

## Objetivo

Verificar que cada ação do movimento está dentro da janela temporal correta:
nem cedo demais (público não está pronto), nem tarde demais (momento já passou).
Timing perfeito multiplica impacto; timing errado desperdiça recursos.

## Checklist

### Análise de Prontidão do Público

- [ ] Volume de busca pelo tema está em tendência ascendente (Google Trends verificado)
- [ ] Conversas espontâneas sobre o tema estão crescendo nas redes sociais (mensurado)
- [ ] O público-alvo demonstra insatisfação ativa com status quo (sinais capturados)
- [ ] Não existe fadiga do público sobre o tema (verificar saturação de conteúdo similar)
- [ ] Eventos catalisadores (notícias, lançamentos, crises) favorecem o momento

### Análise de Janela Competitiva

- [ ] Nenhum concorrente lançou movimento similar nos últimos 30 dias
- [ ] Não existe evento externo que ofuscaria o lançamento (eleições, Copa, crise nacional)
- [ ] Mídia está receptiva ao tema (verificar agenda editorial de veículos-chave)
- [ ] Influenciadores relevantes estão disponíveis para amplificar no período
- [ ] O ciclo de atenção do público permite absorver nova iniciativa (não estão sobrecarregados)

### Validação de Timing Interno

- [ ] Equipe está disponível e preparada para execução na data planejada
- [ ] Todos os assets (conteúdo, design, plataforma) estarão prontos a tempo
- [ ] Orçamento está liberado e acessível para o período de lançamento
- [ ] Não existe conflito com lançamento de produto ou campanha interna
- [ ] Pipeline de conteúdo pós-lançamento está preparado (mínimo 2 semanas)

### Decisão Go/No-Go

- [ ] Checklist de timing foi revisado com pelo menos 48h de antecedência do lançamento
- [ ] Se timing não é ideal, próxima janela alternativa está identificada
- [ ] Critério de "good enough timing" vs "perfeito" está definido (80% é suficiente?)
- [ ] Decisão go/no-go está registrada com responsável e justificativa
- [ ] Plano B para aproveitamento de janela inesperada está preparado (oportunismo planejado)

## Critérios de Aprovação

- Pelo menos 4 de 5 itens de "Prontidão do Público" devem estar positivos
- Pelo menos 4 de 5 itens de "Janela Competitiva" devem estar positivos
- Todos os itens de "Timing Interno" devem estar completos
- Todos os itens de "Decisão Go/No-Go" devem estar completos

## Ação se Falhar

1. Adiar lançamento para próxima janela identificada (não forçar timing ruim)
2. Manter equipe e assets em "modo standby" para janela oportunista
3. Continuar monitoramento de timing com check diário até janela abrir
4. Se timing interno é o problema, resolver gargalo antes de comprometer data
5. Documentar timing perdido para calibrar planejamento futuro
