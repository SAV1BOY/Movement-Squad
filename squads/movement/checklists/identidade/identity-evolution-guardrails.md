# Guardrails de Evolução da Identidade

## Objetivo

Definir regras claras sobre como a identidade do movimento pode evoluir sem perder
sua essência. Identidade estática morre de irrelevância; identidade sem guardrails
morre de incoerência. O equilíbrio é a chave.

## Checklist

### Elementos Imutáveis (Core)

- [ ] Os 3-5 elementos que NUNCA mudam estão listados e aprovados (valores fundacionais)
- [ ] A tese central está protegida como imutável (pode ser refinada, não alterada)
- [ ] As cores primárias da paleta estão definidas como permanentes
- [ ] O tom de voz fundamental (personalidade) está definido como permanente
- [ ] Esses elementos estão documentados com justificativa de por que são imutáveis

### Elementos Flexíveis (Superfície)

- [ ] Lista de elementos que podem mudar livremente está definida (formatos, trends, referências)
- [ ] Limite de variação por elemento flexível está descrito (o que é variação vs descaracterização)
- [ ] Sazonalidade está prevista (como a identidade se adapta a datas, eventos, momentos)
- [ ] Experimentação visual/verbal tem prazo definido (teste de X semanas antes de adotar)
- [ ] Elementos flexíveis são revisados semestralmente para incorporar ou descartar mudanças

### Processo de Mudança

- [ ] Qualquer mudança de identidade passa por proposta formal antes de implementação
- [ ] Mudanças de elementos core exigem aprovação do chief + equipe completa
- [ ] Mudanças de elementos flexíveis exigem aprovação do agente de identidade
- [ ] Toda mudança tem período de teste antes de ser permanente (mínimo 30 dias)
- [ ] Existe processo de rollback se mudança gerar reação negativa significativa

### Documentação de Evolução

- [ ] Histórico de mudanças de identidade está registrado com datas e motivos
- [ ] Versões anteriores de identidade estão arquivadas (não deletadas)
- [ ] Comunidade é comunicada sobre mudanças significativas antes de implementar
- [ ] Feedback da comunidade sobre mudanças é coletado e considerado
- [ ] Existe timeline visual da evolução da identidade para referência

## Critérios de Aprovação

- Todos os itens de "Elementos Imutáveis" devem estar completos
- Todos os itens de "Elementos Flexíveis" devem estar completos
- Todos os itens de "Processo de Mudança" devem estar completos
- Pelo menos 4 de 5 itens de "Documentação" devem estar completos

## Ação se Falhar

1. Reunir equipe para definir coletivamente o que é "core" vs "flexível"
2. Criar documento de brand fundamentals com os elementos imutáveis
3. Estabelecer processo de change request para mudanças de identidade
4. Arquivar todas as versões anteriores de identidade em repositório acessível
5. Comunicar guardrails à equipe toda e parceiros externos
