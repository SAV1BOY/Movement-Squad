# Padrão de Prova para Claims

## Objetivo

Estabelecer padrão mínimo de evidência para qualquer afirmação feita pelo
movimento em comunicações públicas. Claim sem prova suficiente é risco
reputacional e legal; claim com prova robusta é credibilidade construída.

## Checklist

### Classificação de Claims

- [ ] Claims são classificados por tipo: factual (dados), opinião (perspectiva), testemunho (experiência)
- [ ] Claims factuais exigem fonte verificável e citada
- [ ] Claims de opinião são identificados como tal ("acreditamos que" vs "é fato que")
- [ ] Claims de testemunho têm consentimento do autor e são representativos (não cherry-picked)
- [ ] Claims de impacto do movimento são sustentados por dados mensuráveis

### Padrão de Evidência

- [ ] Dados estatísticos citados têm fonte primária identificada e acessível
- [ ] Pesquisas citadas são de fontes respeitáveis e metodologicamente sólidas
- [ ] Dados proprietários são coletados com metodologia documentada
- [ ] Claims comparativos ("somos os maiores", "primeiro a") são verificados antes de publicar
- [ ] Generalização a partir de casos individuais é evitada ou identificada como tal

### Processo de Verificação

- [ ] Todo conteúdo com claims factuais passa por fact-check antes de publicação
- [ ] Existe checklist rápido de fact-check com critérios mínimos (fonte, data, contexto)
- [ ] Pessoa diferente de quem escreveu faz a verificação (olhar fresco)
- [ ] Claims de parceiros e porta-vozes também são verificados (não confiar por default)
- [ ] Histórico de claims verificados é mantido como referência

### Correção de Erros

- [ ] Existe política de correção para claims que se revelam incorretos
- [ ] Correção é publicada no mesmo canal e com alcance similar ao claim original
- [ ] Correções são transparentes ("erramos, corrigimos" sem minimizar)
- [ ] Padrão de erros é analisado para prevenir reincidência
- [ ] Equipe não é punida por identificar claims incorretos (cultura de honestidade)

## Critérios de Aprovação

- Todos os itens de "Classificação" devem estar completos
- Todos os itens de "Padrão de Evidência" devem estar completos
- Todos os itens de "Processo de Verificação" devem estar completos
- Todos os itens de "Correção de Erros" devem estar completos

## Ação se Falhar

1. Auditar últimas 20 publicações por claims sem evidência suficiente
2. Criar checklist de fact-check simplificado (5 perguntas) para uso diário
3. Designar responsável por verificação de claims como etapa no fluxo de publicação
4. Corrigir claims incorretos já publicados com transparência
5. Treinar equipe em literacia de dados e pensamento crítico com workshop prático
