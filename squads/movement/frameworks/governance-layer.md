# Governance Layer — Decisões, Riscos e Ética

## Overview

O Governance Layer é o **sistema imunológico** do movimento. Protege contra riscos, garante ética, estrutura decisões e define limites. Sem governança, movimentos se corrompem, perdem controle ou causam dano — mesmo com as melhores intenções.

Quatro funções da Governance:
1. **Decisão**: como o movimento toma decisões estratégicas e operacionais.
2. **Risco**: identificação e mitigação de riscos (reputacionais, éticos, operacionais).
3. **Limites**: o que o movimento NÃO faz, NÃO diz e NÃO tolera.
4. **Ética**: princípios éticos que governam todas as ações do movimento.

A Governance não é burocracia — é proteção. Um movimento sem governança é uma bomba-relógio.

## Princípios Aplicáveis ao MMOS

1. **Poder distribuído, princípios centralizados**. Líderes locais decidem execução; ética e limites são universais.
2. **Transparência como default**. Decisões significativas devem ser explicáveis à comunidade.
3. **O inimigo é uma ideia, nunca uma pessoa**. Vigilância constante contra desumanização (Girard).
4. **Limites protegem, não restringem**. Saber o que NÃO fazer libera energia para o que SIM.
5. **Crises são inevitáveis**. Ter protocolo antes da crise é 10x mais eficaz que improvisar durante.

## Protocolo de Aplicação

### Passo 1 — Estrutura de Decisão
Definir QUEM decide O QUÊ:

| Tipo de Decisão         | Quem decide           | Processo                        |
|-------------------------|-----------------------|---------------------------------|
| Estratégica (tese, DNA) | Chief + Architect     | Proposta → debate → consenso    |
| Operacional (canais)    | Ciclo + Manifestador  | Proposta → aprovação rápida     |
| Comunitária (rituais)   | Cell Leaders + membros| Consulta → votação informal     |
| Crise (urgente)         | Chief (solo)          | Agir → comunicar → revisar      |
| Ética (dilema)          | Chief + Architect     | Análise ética formal            |

Regra: decisões reversíveis = rápidas. Decisões irreversíveis = cuidadosas.

### Passo 2 — Mapa de Riscos
Identifique e classifique riscos:

| Risco                          | Probabilidade | Impacto  | Mitigação                        |
|--------------------------------|---------------|----------|----------------------------------|
| Cooptação por marca/político    | Média         | Alto     | Política de parcerias clara       |
| Comportamento tóxico de membro  | Alta          | Médio    | Código de conduta + moderação     |
| Desvio de tese por líder local  | Média         | Alto     | Treinamento + review semestral    |
| Crise de reputação em rede      | Média         | Alto     | Protocolo de crise pré-definido   |
| Burnout do core team            | Alta          | Alto     | Rotação, limites de carga         |
| Dependência de uma plataforma   | Média         | Médio    | Presença multicanal               |
| Uso indevido da marca           | Baixa         | Alto     | Registro + guidelines claras      |

Atualizar mapa trimestralmente.

### Passo 3 — Código de Conduta
Todo movimento precisa de um código de conduta público:

**Estrutura mínima**:
1. **Propósito**: por que este código existe.
2. **Comportamentos esperados**: o que membros devem fazer.
3. **Comportamentos proibidos**: o que não é tolerado.
4. **Consequências**: o que acontece se o código for violado.
5. **Canal de denúncia**: como reportar violações (anônimo, se possível).
6. **Processo de revisão**: como casos são analisados e decididos.

Comportamentos proibidos essenciais:
- Discurso de ódio, discriminação, assédio.
- Desumanização de indivíduos ou grupos.
- Uso do movimento para ganho pessoal indevido.
- Divulgação de informações privadas de membros.
- Comportamento que contradiz os valores declarados.

### Passo 4 — Protocolo de Crise
Quando uma crise acontece (e vai acontecer):

**Etapa 1 — Avaliar (0-2 horas)**:
- O que aconteceu exatamente? (fatos, não suposições)
- Qual o impacto real e potencial?
- Quem está envolvido?
- Classifique: baixa / média / alta severidade.

**Etapa 2 — Decidir (2-6 horas)**:
- Chief define posicionamento com Architect.
- Consultar assessoria jurídica se necessário.
- Redigir comunicado (transparente, empático, responsável).

**Etapa 3 — Comunicar (6-24 horas)**:
- Interno primeiro (comunidade), depois externo (público).
- Um porta-voz, uma mensagem consistente.
- Reconhecer o problema + ação concreta + compromisso de acompanhamento.

**Etapa 4 — Resolver (1-7 dias)**:
- Implementar ação corretiva.
- Comunicar progresso à comunidade.
- Documentar aprendizado no Learning Layer.

### Passo 5 — Framework Ético
Para decisões com implicação ética, use o teste de 5 perguntas:

1. **Teste do jornal**: se essa decisão fosse manchete de jornal amanhã, nos orgulharíamos?
2. **Teste do membro**: se um membro fundador visse isso, concordaria que reflete nossos valores?
3. **Teste de reversibilidade**: se isso der errado, conseguimos reverter?
4. **Teste de universalidade**: se todos os movimentos fizessem isso, o mundo seria melhor ou pior?
5. **Teste do bode expiatório** (Girard): estamos causando dano a uma pessoa/grupo para unir os demais?

Se qualquer teste falhar, reconsidere a decisão.

## Quando Usar / Não Usar

### Usar quando:
- Sempre. Governance é contínua.
- Lançamento do movimento (definir estrutura de decisão e código de conduta).
- Qualquer situação de crise.
- Decisões que envolvem ética, parcerias ou limites.
- Revisão trimestral de riscos.

### Não usar quando:
- Nunca desative a Governance. É tentador "simplificar" removendo regras, mas o custo de uma crise sem protocolo é imenso.

## Agentes Responsáveis

| Agente    | Papel no Governance Layer                                    |
|-----------|--------------------------------------------------------------|
| Chief     | Líder da camada. Toma decisões de crise. Define limites.     |
| Architect | Co-decide em questões estratégicas e éticas.                 |
| Impacto   | Monitora riscos e alertas com base em dados.                 |
| Todos     | Seguem código de conduta e reportam violações.               |

## Inputs e Outputs

**Inputs**:
- Health Score e alertas (Measurement Layer).
- Feedback da comunidade.
- Sinais do Radar Layer (mudanças culturais que geram novos riscos).
- Incidentes e crises.

**Outputs**:
- Estrutura de decisão documentada.
- Mapa de riscos atualizado trimestralmente.
- Código de conduta público.
- Protocolo de crise pré-definido.
- Registro de decisões éticas e suas justificativas.

## Exemplo Aplicado

### Caso: Crise em movimento de diversidade corporativa

**Incidente**: um embaixador do movimento fez post polêmico generalizando sobre "homens brancos em posição de poder" — linguagem que desumaniza um grupo, contradizendo o valor do movimento de "inclusão para todos."

**Protocolo ativado**:
1. **Avaliar**: post real, alto impacto (viralizado), embaixador oficial envolvido.
2. **Decidir**: Chief + Architect concordam: a frase contradiz o valor de inclusão. O embaixador errou, mas não agiu com má-fé.
3. **Comunicar**: mensagem interna — "Valorizamos a indignação contra injustiça E o compromisso com humanizar todos, inclusive quem está em posição de privilégio. Criticamos estruturas, não identidades." Mensagem externa (stories): mesma essência, tom mais conciso.
4. **Resolver**: conversa privada com embaixador (acolher + educar, não punir). Post removido. Treinamento de comunicação para todos os embaixadores.
5. **Aprender**: insight registrado — "Precisamos de guidelines de linguagem mais claras para embaixadores, especialmente sobre a fronteira entre criticar estrutura vs. atacar identidade."

**Teste ético aplicado**:
- Teste do jornal: "Movimento demite embaixador por post polêmico" ❌ / "Movimento educa embaixador e reafirma valores" ✅
- Teste de Girard: post original usava linguagem de bode expiatório. Movimento corrigiu.
