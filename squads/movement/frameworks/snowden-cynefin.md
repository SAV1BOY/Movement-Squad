# Snowden — Cynefin Framework

## Overview

Dave Snowden criou o **Cynefin** (pronuncia-se "ku-NÉ-vin", do galês "habitat") como framework de tomada de decisão baseado na natureza do problema que se enfrenta. A premissa: não existe uma única forma correta de agir — depende de em qual domínio o problema se encontra.

### Os Cinco Domínios:

1. **Claro (Simple/Obvious)**: relação causa-efeito é óbvia para todos. Resposta: **Sentir → Categorizar → Responder**. Usar melhores práticas. Exemplo: processo de onboarding padronizado.

2. **Complicado**: relação causa-efeito existe mas requer análise/expertise. Resposta: **Sentir → Analisar → Responder**. Usar boas práticas com especialistas. Exemplo: análise de dados de engajamento.

3. **Complexo**: relação causa-efeito só é visível em retrospecto. Padrões emergem mas não são previsíveis. Resposta: **Sondar → Sentir → Responder**. Experimentar com safe-to-fail probes. Exemplo: testar narrativas de movimento.

4. **Caótico**: sem relação causa-efeito perceptível. Crise total. Resposta: **Agir → Sentir → Responder**. Estabilizar primeiro, depois analisar. Exemplo: crise de reputação viral.

5. **Desordem (Disorder)**: não sabemos em qual domínio estamos. O maior perigo — tendemos a aplicar abordagem do domínio com que estamos mais confortáveis, que pode ser errada.

## Princípios Aplicáveis ao MMOS

1. **Movimentos operam principalmente no domínio Complexo**. Cultura, comportamento e identidade são sistemas complexos adaptativos.
2. **No complexo, não planeje — sonde**. Lançar "probes" (experimentos pequenos) e observar o que emerge.
3. **Melhores práticas são para o Claro. No Complexo, use práticas emergentes**. Copiar playbook de outro movimento pode falhar.
4. **Crises jogam o movimento no Caótico**. A resposta deve ser: agir para estabilizar, depois analisar.
5. **O maior risco é tratar Complexo como Complicado** — analisar excessivamente em vez de experimentar.

## Protocolo de Aplicação

### Passo 1 — Classificar o Domínio do Problema
Para cada decisão/desafio do movimento, pergunte:

| Pergunta                                          | Se sim → Domínio       |
|---------------------------------------------------|------------------------|
| A solução é óbvia e replicável?                   | Claro                  |
| A solução requer análise especializada?            | Complicado             |
| Não sabemos o que vai funcionar até testar?        | Complexo               |
| Estamos em crise e precisamos agir já?             | Caótico                |
| Não sabemos nem que tipo de problema é?            | Desordem               |

### Passo 2 — Aplicar a Abordagem Correta

**Claro**: padronize. Crie checklist, SOP, template. Delegue.
- No MMOS: onboarding de membros, publicação de conteúdo recorrente, FAQ.

**Complicado**: consulte especialistas e analise. Várias soluções boas são possíveis.
- No MMOS: análise de dados de engajamento, estratégia de canais, precificação.

**Complexo**: experimente. Lance safe-to-fail probes (experimentos que não causam dano se falharem).
- No MMOS: testar uma nova narrativa com público pequeno, experimentar formato de ritual, testar canal.

**Caótico**: aja primeiro. Estabilize. Depois entenda.
- No MMOS: resposta a crise de reputação, controvérsia viral, ataque de adversário.

**Desordem**: divida o problema em partes e classifique cada parte separadamente.

### Passo 3 — Design de Safe-to-Fail Probes (para o Complexo)
Critérios para um bom probe:
- **Barato**: pouco investimento de tempo/dinheiro.
- **Rápido**: resultado observável em dias/semanas, não meses.
- **Seguro**: se falhar, não causa dano irreversível ao movimento.
- **Informativo**: o resultado (sucesso ou falha) ensina algo.
- **Múltiplo**: lance vários probes em paralelo, não apenas um.

Formato: "Vamos testar [hipótese] fazendo [ação] com [público pequeno] durante [período curto] e medindo [indicador]."

### Passo 4 — Escalar o que Emerge
- Probe funcionou → ampliar gradualmente (não escalar de uma vez).
- Probe falhou → documentar aprendizado, lançar novo probe.
- Padrão emergiu → formalizar como prática (mover de Complexo para Complicado).
- Nunca escalar um probe antes de confirmar o padrão em pelo menos 2-3 iterações.

### Passo 5 — Evitar a Armadilha da Desordem
Sinais de que você está na Desordem:
- Discussões intermináveis sem decisão.
- Cada pessoa defende abordagem diferente sem critério.
- Paralisia por análise.
Solução: pare, classifique o domínio explicitamente com o time, depois escolha abordagem.

## Quando Usar / Não Usar

### Usar quando:
- Tomando qualquer decisão estratégica sobre o movimento.
- Decidindo entre planejar vs. experimentar.
- Respondendo a uma crise.
- A equipe discorda sobre a abordagem (provavelmente estão em Desordem).

### Não usar quando:
- O problema é claramente operacional e já tem processo definido.
- Estamos em execução tática com plano validado.
- O framework não é familiar à equipe (treine antes de aplicar em reunião).

## Integração com Movement Squad

| Camada MMOS         | Domínio Cynefin predominante                               |
|----------------------|------------------------------------------------------------|
| Radar Layer          | Complexo (sinais emergem, não são previsíveis)              |
| Thesis Layer         | Complexo/Complicado (hipótese + análise)                   |
| Creation Layer       | Complexo (testar artefatos com probes)                     |
| Activation Layer     | Complicado (canais e táticas requerem expertise)           |
| Measurement Layer    | Complicado (análise de dados)                              |
| Governance Layer     | Todos (decisões em múltiplos domínios)                     |
| Learning Layer       | Move práticas de Complexo para Complicado para Claro       |

**Agentes principais**: Chief (classificação de domínio), todos os agentes (aplicam abordagem adequada ao domínio).

## Exemplo Aplicado

### Caso: Lançamento de movimento cultural para uma marca de moda sustentável

**Classificação por desafio**:
- Que narrativa vai ressoar? → **Complexo** → Lançar 3 probes de narrativa diferentes em grupos de Instagram.
- Qual canal de ativação usar? → **Complicado** → Analisar dados demográficos e benchmark do setor.
- Como responder ao boicote de concorrente? → **Caótico** → Agir rápido, posicionar-se publicamente, depois analisar.
- Como processar novos membros? → **Claro** → Criar fluxo padrão de onboarding no e-mail.

**Probes lançados (Complexo)**:
1. Narrativa A: "Moda que não custa o planeta" (eco-culpa).
2. Narrativa B: "Vista o futuro" (aspiracional).
3. Narrativa C: "Bonito e correto" (pragmático).
Cada uma testada com 500 pessoas por 2 semanas. Métrica: taxa de compartilhamento + comentários qualitativos.

**Resultado**: Narrativa B gerou 3x mais compartilhamento. Padrão emergente: público quer aspiração, não culpa. Escalar gradualmente narrativa B para campanha principal.
